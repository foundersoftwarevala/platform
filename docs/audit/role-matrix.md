## Audit boundary

Developer Manager writes to `audit_logs` in application code and reads the
same table for its audit screen ([dev-manager.server.ts:67](../../src/lib/dev-manager.server.ts#L67),
[dev-manager.server.ts:91](../../src/lib/dev-manager.server.ts#L91),
[dev-manager.server.ts:772](../../src/lib/dev-manager.server.ts#L772)). The supplied
schema shows `audit_logs` fields including `actor`, `action`, `entity_type`,
`entity_id`, `metadata`, `ip`, and `occurred_at`, but no before/after columns
([public-schema.sql:23972](../../supabase/schema/public-schema.sql#L23972)).
No append-only or tamper-evident enforcement for this table is visible; the
listed policy denies anonymous writes only ([public-schema.sql:49390](../../supabase/schema/public-schema.sql#L49390)).
