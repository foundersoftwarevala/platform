Root cause:
Author lifecycle controls were derived from a hard-coded submit-state set.
That set exposed Submit for rejected products even though the existing API
permits rejected -> draft only; the request therefore failed with HTTP 409.
The separate AddProduct.tsx and MarketplaceCatalogAdmin.tsx surfaces are
manager/operator flows and were not repurposed for author lifecycle controls.

Change:
- Share the AUTHOR_TRANSITIONS map between the API and author UI action helper.
- Drafts expose Edit and Submit.
- Submitted products expose Withdraw.
- Changes-requested products expose Edit and Submit.
- Rejected products expose Edit and Return to draft; after that succeeds they
  can be submitted from draft.
- Approved products display a read-only status badge and no author actions.
- Existing loading, empty, API error/retry, and mutation error states remain
  in the author workspace.
